# Crypto Time Ledger

Immutable timestamped ledger for cryptographic algorithm state — build a verifiable
chain of "what algorithm was used at time T" anchored to RFC 3161 Trusted Timestamps.

## Status

v0.1.0 — **core + storage + TSR verification modules** (this PR). **CLI is next.**

## Quick Start

```bash
npm install
npm test        # 29 tests (13 core + 8 storage + 8 TSR)
npm run typecheck
```

## Generate fixtures

```bash
node scripts/seed-tsr.mjs
```

Requires `openssl` on PATH. May print the benign warning:

```
error:...NCONF_get_string:no value:...name=certs
```

This is a known OpenSSL `ts -reply` quirk — the response is still valid with exactly
one signer certificate (from `ts -query -cert`). Not an error in our usage.

Output: 4 `.tsr` fixtures + `pinned-certs.pem` in `test/fixtures/tsr/`.

## Dependencies

| Package | Version | Purpose |
|---------|---------|---------|
| `pkijs` | ^3.4.0 | RFC 3161 TSR/CMS parsing + CMS signature verification |

Core algorithms (`canonicalize`, chain integrity, SQLite storage, CLI) are **zero new
runtime dependencies**. The TSR verification module uses `pkijs` because hand-rolled
ASN.1/CMS/X.509 parsing is high-risk (multiple concrete bugs found during exploration).
`pkijs` is battle-tested and delegates cryptographic operations to the platform's
`webcrypto` (Node's built-in crypto). The glue layer only handles:

- TSR file loading and CMS structure parsing
- `eContentType` override so pkijs skips its "needs original data" branch
- `messageImprint` comparison (SHA-256 hex match)
- Trust-anchor pinning (SPKI DER comparison against a known-TSA allowlist)
- Fail-closed behaviour when any check cannot be satisfied

## `.gitignore` note

`test/fixtures/tsr/` is partially ignored. Only the following are excluded:

```
*.key        — private keys, never leave this machine
tsa*.pem     — TSA signing certificates (test-only, not trust anchors)
*.cnf        — OpenSSL TSA config (generated by seed-tsr.mjs)
*.tsq        — TSA queries (generated by seed-tsr.mjs)
tsaserial    — serial counter (generated by seed-tsr.mjs)
```

The following are **intentionally tracked**:

```
*.tsr        — RFC 3161 TSR fixtures (test data)
meta.json    — digest → TSA mapping
pinned-certs.pem — public trust anchors (TSA 1–3 root certificates)
```

Use `git add test/fixtures/tsr/` (no `-A` / no `.`) to stage only the tracked files.

## Architecture

```
src/
  core.ts      — LedgerBlock schema + canonicalize + computeHash
  storage.ts   — SQLite persistence (LedgerStore interface)
  tsr.ts       — TSR verification (makeVerifyTSR / verifyTSR)

test/
  core.test.ts
  storage.test.ts
  tsr.test.ts
  fixtures/tsr/ — fixture data (see .gitignore note above)

scripts/
  seed-tsr.mjs  — generates test fixtures (requires openssl)
  openssl-minimal.cnf
```
