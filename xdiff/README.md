## 二、🔴 抓到的真 bug——✅ 判准，硬核

> **cp 的密钥派生用了 `G(d)` 而非 `G(d‖k)`，漏拼域分隔符 `k`（`k=3`）。**
>
> - **位置：`fibemate-core/src/kem/ml-kem-768.js:548`，`const seed = sha3_512(d);`**
> - **对照：主仓 `packages/pqc-kem/src/ml-kem-768.js:225` 写作 `sha3_512(new Uint8Array([...d,K]))`，并注明 `// G(d‖k) — domain separator k`**
> - **证据：cp 的 ρ 等于 `SHA3-512(d)` 前 32 字节，与 9 个候选输入逐一比对后唯一命中这一项**

——✅ **判准，硬核**。

**且一处更硬**——✅：

> **"只修这一处不够。在副本上应用修复后，ρ 归位（`keySchedule` 转 `standard`），pk 仍有 1148 字节不同，互操作仍失败。继续把 keygen 的矩阵索引改成标准顺序 `XOF(ρ‖j‖i)` 后，cp 自身 roundtrip 从 24/24 掉到 16/24——说明它的 keygen 与 encaps 是成对自洽的（A 与 AT 互为转置），单点修改会破坏内部一致性。"**>   
> **"结论：cp 的偏离是结构性的，需要按 FIPS 203 逐段核对整个密钥生成与封装流程，不是一行补丁。以上改动都在副本上验证，未修改任何源文件。"**

——✅ **判准，硬核**。**"`A` 与 `AT` 互为转置"**——✅ **判准**。
